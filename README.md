## Exercise 4: อธิบายว่า Workflow จะเริ่มเมื่อใด และ Job deploy ทำอะไร

- Workflow จะเริ่มทำงานเองทุกครั้งที่ push โค้ดเข้า branch main (หรือกดรันเองที่แท็บ Actions ก็ได้)
- Job deploy จะทำตามขั้นตอนที่เขียนไว้ในไฟล์ deploy.yml ตามลำดับ 
  - ดึงโค้ดจาก repository
  - เช็คว่ามีไฟล์ index.html ไหม ถ้าไม่มีจะหยุดทันที
  - ตั้งค่า GitHub Pages
   - รวมไฟล์เว็บเป็นชุดเดียว
   - เอาขึ้น GitHub Pages ให้คนเข้าดูได้

## คำถามท้ายแลป

### 1) GitHub Actions แตกต่างจาก GitHub Pages อย่างไร?

- GitHub Pages เป็นที่เก็บและแสดงหน้าเว็บให้คนเข้าดูผ่าน URL
- GitHub Actions เป็นระบบทำงานอัตโนมัติ ใช้สั่งให้ทำงานบางอย่างเมื่อมีเหตุการณ์ เช่น push แล้ว deploy เว็บให้เอง

### 2) เหตุใดจึงเลือก trigger ด้วย push ที่ branch main?

- main เป็น branch หลักที่เก็บโค้ดเวอร์ชันล่าสุดที่ใช้งานจริง
- พอ push เข้า main เว็บก็อัปเดตเองทันที ไม่ต้อง deploy ด้วยมือ
- ถ้าแก้โค้ดใน branch อื่นที่ยังไม่เสร็จ เว็บจริงจะไม่ถูกเปลี่ยน

### 3) ถ้าแก้ไฟล์ในเครื่องแต่ไม่ได้ push เว็บไซต์จะเปลี่ยนหรือไม่ เพราะเหตุใด?

- ไม่เปลี่ยน เพราะเว็บที่คนเห็นมาจากโค้ดบน GitHub ไม่ใช่โค้ดในเครื่องเรา
- Workflow จะเริ่มก็ต่อเมื่อมีการ push ขึ้นไป ถ้าไม่ push GitHub ก็ไม่รู้ว่าเราแก้อะไร

### 4) เหตุใดโปรเจกต์ PHP + MySQL จึงไม่สามารถนำไปรันบน GitHub Pages ได้โดยตรง?

- GitHub Pages แค่ส่งไฟล์ HTML, CSS, JavaScript ให้เบราว์เซอร์ ไม่ได้ประมวลผลอะไรฝั่งเซิร์ฟเวอร์
- PHP ต้องมีเซิร์ฟเวอร์คอยรันโค้ด และ MySQL ต้องมีฐานข้อมูลที่ทำงานอยู่ตลอดเวลา ซึ่ง GitHub Pages ไม่มีให้

### 5) อธิบายขั้นตอนการค้นหาสาเหตุ เมื่อ Workflow มีสถานะ Failed

1. เข้าแท็บ Actions แล้วกดเข้าไปที่ run ที่เป็น ❌
2. เปิดดู step ที่มีเครื่องหมายแดง แล้วอ่านข้อความ error ใน log
3. เช็คสาเหตุที่เจอบ่อย เช่น ยังไม่ได้ตั้ง Pages เป็น GitHub Actions, สะกดชื่อไฟล์หรือโฟลเดอร์ผิด, ย่อหน้าใน YAML ผิด
4. ถ้ายังไม่เข้าใจ error ให้ค้นหาใน Google หรือถาม AI
5. แก้ไข แล้ว commit และ push ใหม่ จากนั้นดูว่า run ใหม่ผ่านหรือไม่
